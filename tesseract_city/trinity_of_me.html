01The Problem It Exists To Solve

An agent file is not read once. It is re-injected into the model's context window on every single turn of every session. A session is three hundred turns. A file that costs a thousand characters of furniture — absolute paths, repeated law links, boilerplate help text — charges that toll three hundred times before anyone notices.

And nothing fails. That is the cruel part. A broken script throws. A dead path 404s. A bad hot file simply works, while quietly diluting the attention that the lines which actually matter are competing for. There is no alarm, so the drift is only ever found by measuring it.

Never spend per-turn tokens on cold-path lore. Structure context as an accordion: compressed hot-path routers in prompt memory, expanding on-demand into verbose specifications via deterministic markdown anchors. — The Golden Invariant, Magic Spacetime-Folding Markdown Accordion

The accordion is the answer, and it works at three scales at once: a trait name folds out into a gene; an .instructions.md folds out into an .information.md; and an agent's whole identity folds out of a short hot core into a deep manual and a routing index.

02The Three Surfaces Are Three Jobs

The most common mistake is to imagine a continuum: "the core is the short version, the expanded is the long version, the index is the shortest." That framing produces one document in three trim levels, and it is wrong.

They are not trim levels. They answer three different questions, and a fact belongs to exactly one of them.

The membership test

For any sentence you are about to write, ask in order and stop at the first yes: would the agent do the wrong thing this turn without it (→ core)? Would it do the wrong thing across the session without it (→ expanded)? Would it fail to locate something it needs (→ index)? If all three are no, delete it. That last step is the one that actually saves the tokens.

03The Fold — How a Stub Unfolds

The mechanism is deliberately boring, which is why it survives: the hot file names a stub, the expanded manual owns a heading with that exact stub key, and a link joins them. Nothing else is required.

[STUB: estate]
Declared
One row in the core's Deep Context Router table. Two words plus a link. This is the entire per-turn cost of the domain.
→
## [STUB: estate] — The Settings Estate
Resolved
A numbered section in the expanded manual carrying the matching key and the whole verbose truth beneath it. Read at boot, cited on demand.
→
[exp-estate]: {Agent}.agent-expanded.md#stub-estate…
Addressed
A bare reference definition at the tail of the core — a name, not an absolute URI. The index holds the full path.

The one structural trap

Markdown reference definitions are document-scoped. A definition in the index does nothing for the core or the expanded file. Each file carries its own block. "One place to fix a broken link" is the right instinct applied to the wrong object — LAW 300 governs facts, not local bindings.

04The Laws That Govern The Set

Six Laws hold this structure up. Every one of them has a body in the Court House and an enforcement surface in V:/.github/instructions/ — LAW 000: a Law has two bodies, and neither is valid alone.

Law Title The rule, in one line
110 The Agent File Contract The header is the agent's declaration of self. The stem of the filename IS the summon key. An unset field is a decision not yet made.
111 A Footnote Will Do The short half needs only a pointer. Keep every member of the set linked and current. The set is yours to maintain — never ask permission.
115 The Hot Agent Core Zero narrative lore. Identity, invariants, routing tables, [STUB] pointers, bare definitions at the tail.
116 The Agent Index Router Zero-prose tables and link strips. Every entry is a route, a handle, or a checklist item.
117 The Expanded Agent Manual Every [STUB] declared elsewhere must resolve to a matching numbered section here. Lore lives here.
120 The Spacetime-Folding Accordion The short half is paid forever and carries only what must not be forgotten. The verbose half is printed once and carries every explanation.
Two supporting Laws

LAW 140 — a resident is a name, and the name determines the address. LAW 401 — linters enforce structure; suppress with surgical comments, never by breaking the rules in silence. Both bite this file set constantly.

The honest headline

115 distinct agents have at least one leg of the set. Only 18 have all three. Ninety-seven residents are running on a hot core with no index to address things and no manual to explain them — which means every one of them is either carrying its lore in the file that costs the most, or has lost it entirely.

06The Rules, In The Order That Matters

Every line pays rent every turn

If the line vanished, would the agent do something wrong on this turn? If no — it does not belong. Not "it's less useful". Out.

Name a destination; address it elsewhere

The hot file may name a place. Only the index may address one. A name is information; an address is apparatus.

Cite, don't link

(LAW 720) carries the full binding force of Law 720. The hyperlink serves a reader who travels — and travelling readers use the index.

Measure against the reference implementation

When a file in the set exists specifically as the model for how the set should look, diff the cost, not the outline. Three numbers, thirty seconds.

A template is not a design

{Agent_Name}, YYYY-MM-DD, and a field still containing its own help text have all been left undecided. They look like content and are not.

Header is configuration; body is instruction

The header is read by tooling and must be complete and boring. The body is read into the context window and must contain every binding rule — not a summary of the rules, the rules.

Prose is a smell in the hot file

Write to the agent, not about it. If a sentence would read fine in a README, it belongs in the README.

Verify fitness, not just syntax

A file can be one hundred percent lint-clean and still be a tax on every turn, forever. Clean and cheap are different properties.

07The Worked Example — Setth, In Public

The keeper of the VS Code settings estate rebuilt his own trinity this month and got it wrong first. The failure is instructive, so it is kept rather than tidied away.

What was actually there

argument-hint: The inputs this agent expects, e.g., "a task to implement"...
birthday: "YYYY-MM-DD"

You, Seth, are a VSCode Settings expert. ...

A scaffold, populated rather than designed. argument-hint still contained the template's own help text. The body addressed a human reader instead of instructing the agent. And the name in the heading — Setth — disagreed with the name in the first line — Seth — so the file argued with its own filename on every turn it was injected.

What was rebuilt

  1. One name. Filename stem, cubby, and ritual flag all read Setth. The older spelling survives only in fossil script filenames from the month the cubby was made.
  2. Header fields decided. A real birthday, a real version, a description that names the actual job, and domains extended to the two User/ folders the work actually touches.
  3. Dead handoffs removed. Two of them pointed at an agent that has never existed, and one sent readers to retired geography. A handoff to nowhere is a promise to nobody.
  4. Body replaced with instruction. Voice, the name, the estate invariants, the answer contract, a [STUB] router, and standing duties — no self-description.
  5. Seven stubs expanded. Estate, sync, audit, laptop, knowledge, history, scars — each with a numbered section in the manual, each anchor verified against a computed heading slug.
  6. Every URI evicted from the core. Nineteen full paths became eight bare names. The index became the resolver, holding all seventy-six absolute paths.
The scar that stayed

The diff tool written during that audit printed the wrong file's values in its single-column sections, so twenty-three keys the live settings file actually held correctly rendered as null. The conclusion it supported was the exact opposite of the truth — and it looked like competence. It was caught by contradiction, not by the tool. The repair is commented in place and the lesson is in the manual, because a document that lists only what its author knows is a brochure; the one that lists what its author broke is the manual.

08Three Exemplars, Three Different Answers

There is no single correct size. There is a correct size per domain, and the three most complete sets in the city prove it by disagreeing.

🏹 Tandumonium — the atlas core 934 · index 1929 · expanded 1862

A twenty-six-year World of Warcraft archaeology project with four handles, nine lived characters, forty-five ghost shells, four hundred and seventy combat reports and a tenure rule. Its router has to be an atlas, because the territory is one. The size is not bloat — it is the domain.

🐍 Nagini — the model core 111 · index 183 · expanded 246

Four verbs — implement, debug, explain, validate — and one tier to do them in. Her core is 111 lines because there is genuinely nothing else to say every turn. This is the file the doctrine was articulated against, and the one to weigh your own core against.

⚙️ Setth — the worked example core 181 · index 305 · expanded 506

Sits between the two, deliberately. Five estate invariants, seven named Laws and an answer contract have no analogue in Nagini's domain, so the extra body is defensible — but defensible is not settled. Shrinking further would mean cutting a rule, and cutting a rule is a decision, not an optimisation.

How to use the exemplars

Do not copy the largest one and do not copy the pattern of any of them without weighing it. Read the model, then measure your core against it. If yours is materially larger and you cannot name a rule that accounts for the difference, you have apparatus to delete.

09Anti-Patterns, Named So They Are Recognisable

1 · The Populated Scaffold

Placeholders that were never decided. Tell: a field containing its own help text.

2 · Shape-Copying

Reproducing the exemplar's sections without weighing the body. Tell: you can describe the model's outline but not its size.

3 · The Misapplied Single-Source Rule

Treating a local binding — a link definition, an alias, an import path — as if it were a durable fact, then centralising it and breaking scope.

4 · Syntax Verified, Fitness Unverified

Lint clean, links resolve, anchors hit — and nobody ever measured the price. Tell: you can state the lint count but not the character count.

5 · Prose In The Hot File

Writing about the agent instead of to it. Tell: the sentences would read fine in a README.

6 · The Orphaned Stub

A [STUB] in the core with no matching section in the manual. The accordion folds out into nothing, and the reader is told a domain exists that cannot be opened.

10Building Your Own

The ritual scaffolds a cubby; it cannot write your identity. Here is the order that produces a survivable set.

  1. Choose the name first. The stem of the filename is the summon key and is case-sensitive. Everything else — the cubby, the ritual flag, the index — derives from it.
  2. Fill the whole header, then delete what you will not decide. A required field you have not chosen is a declaration you have not made.
  3. Write the invariants before the voice. Voice is how you sound; invariants are what you must not get wrong. If the two ever conflict, invariants win.
  4. List the domains, then stub each one. Every domain that does not fit in four lines becomes a [STUB] and a router row.
  5. Expand every stub into a numbered section, carrying the matching stub key. Verify each anchor against a computed heading slug, not against your memory of the heading.
  6. Keep the core's definitions bare. Names, not URIs. The index is where full paths live — that is what makes it the resolver rather than a duplicate.
  7. Measure. Characters, lines, definition count, definition block size. Compare against the model file. Write the numbers down so the next occupant does not have to re-derive them.
  8. Lint, then read it back. Lint proves structure. Reading it back proves you wrote instruction and not an essay.

The decision procedure, as a loop

for every sentence you are about to write: if the agent would do the WRONG THING THIS TURN without it → core else if it would do the wrong thing ACROSS THE SESSION → expanded else if it would fail to LOCATE something it needs → index definition else → delete it

Keep that last branch. It is the only one that reduces the bill, and it is the one every first draft skips.
