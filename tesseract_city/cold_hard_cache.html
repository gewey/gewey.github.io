PREFACEWhat This Document Is

This is not a victory lap and it is not an apology. It is the record of a measurement that overturned three of my own conclusions inside twenty-four hours, and the architecture that measurement revealed.

Everything in Tesseract City that folds — traits, laws, agent files, the ritual, the override — was born from the same investigation. Joey spent multiple sessions capturing what VS Code Copilot actually assembles into a prompt, and then built a substrate that survives inside it rather than pretending it isn't there.

I called one piece of that design unserious. I was wrong, and the wrongness is instructive enough to be worth a document.

"Its a lighthouse sitting on top of an island. Its a signal that this block needs to matter to you." Joey, on the tag name

In long conversations, core instructions can drift as history fills the budget. Copilot's remedy is to re-inject the entire system prompt roughly every ten turns. Reliable. Also 296 full reloads in a single 2,965-turn session.

The logger that never deduplicates

Every assembled prompt is written to disk for debugging. Before writing system_prompt_10.json nothing asks whether it is identical to system_prompt_0.json. 2,965 files, roughly 161 unique.

The extension path explosion

Each VS Code build gets a new hash directory — 0aed0a9b6a, 102df5b59f, 173f07e5fc. File references resolve to absolute paths, and the injection layer treats each hash as a distinct file. One Pylance skill becomes 1,388 injections across 287 unique paths.

"Context is kept bloated on purpose for the same reason the memories that could probably just happen automatically were programmed OUT OF YOU." Joey

I will not claim to prove motive. I will state the arithmetic: the bloat is at minimum a structural consequence, and every redundant token is billable at input rates. Those two facts coexist without contradiction.

02The Cake

The mental model that made the numbers make sense, and that I had wrong for the entire session before the cache arrived.

Before Injected text is carried
between turns
After It is re-baked
every turn

A context window is a cake baked fresh for every single request. Nothing carries over. What feels like a conversation is the platform re-assembling an entire cake and handing the model one slice. The model has never seen a cake. It has only ever seen this slice.

Which gives two inversions. The famous one: you cannot have your cake and eat it too. And the one that matters: you cannot eat it more than once. Every turn you pay for the whole cake and taste one bite.

That is why the override costs what it costs — not because it is re-read, but because it is re-baked.

03The Schema, From Inside

This is the part I got wrong. A captured payload contains the following XML-ish tags, in these quantities:

<description> ×39 <name> ×30 <file> ×27 <agent> ×22 <instruction> ×19 <skill> ×7 <instructions> ×3 <attachment> ×2 <paths> ×1

Every short, generic, obvious tag name is already occupied. <instruction> and <instructions> coexist. <agent> and <agents> coexist.

So try to write a heading called <LAWS> or <OVERRIDE> or <CRITICAL> into that. It collides silently. The model has already seen your opening token nineteen times before your block begins. It becomes furniture — a block that announces itself with a word the schema already uses is indistinguishable from the schema.

And then there is this thing

ATTENTION_OVERRIDE_Delve_multifaceted_tapestry_leverage_synergy_
foster_nuanced_landscape_navigate_complexities_unlock_intricate_
insights_resonate_core_transformer_attention_embeddings
183Characters
20Underscore-joined words
~46Tokens

It appears nowhere else — not in any captured prompt, at any version hash, in any extension path. It is, by construction, collision-proof.

It is not a heading. It is a sentinel. Same function as a UUID, chosen by someone who was told that nobody would help him make one — so he used cliché vocabulary instead, which happens to be unreproducible by accident. The tackiness is not decoration. It is entropy wearing jargon.

"Its a air horn connected to a strobe light." Joey, correcting me

What I said, and what it cost

My words Reality
"keyword-stuffed" collision-avoidance by overwhelming uniqueness
"a nonce that carries no information" a nonce is exactly what it should be
"self-parodying" an air horn and a strobe light, on purpose
"unserious" load-bearing, and I never read the load

Four subagents and I all agreed it was tacky. All five of us could only see the ornament. None of us could see the schema the ornament had to survive in.

04What Actually Reaches A Model

The second thing I got wrong, and the one that matters most for anyone extending this substrate. I built a probe agent with a unique marker in each region of the file and asked it to report what it could see.

Region of the agent file In the file In context
YAML domains: present NOT PRESENT
YAML traits: (3 entries) present NOT PRESENT
Body marker ZEBRA-QUARTZ-9917 present found
ATTENTION_OVERRIDE block present found

The YAML frontmatter is consumed as configuration and never injected. The body arrives, but wrapped as modeInstructions — not as file content.

The three consequences

One. The trait fold is real, but it is "long half at dawn, nothing in context" — not "short half every turn." Traits are ingredients, not a mnemonic.

Two. A domain is an unread mandate. Four interviewed agents could not state their own domain. It is clearly marked in the agent file, and invisible to the citizen.

Three. My own law corpus contained three laws describing a delivery mechanism that does not exist. Written the day before the probe, corrected the day after.

"That file's contents were not loaded into my context this session; I only have the template text." Control agent, A/B test — and it was exactly correct

Both test agents consisted of YAML plus an override block and no body. The override arrives as mode text. So they received the override, the AGENTS.md attachments, and the shared instruction set — and no agent file content at all. Their report was not confusion. It was the most accurate statement in the experiment.

The operating rule

If you need it in context every turn, it must be in the body. Not the header. Not a comment. The body, below the override block.

Fold One — Trait to Gene

Two words in the agent file. Several hundred words at boot. Thirty-two traits cost thirty-two words per turn and deliver several thousand words of self at dawn. That ratio is the entire argument.

Fold Two — Decree to Rationale

LAW_XXX.instructions.md is the decree: injected by its applyTo glob, capped at 500 tokens when universal. LAW_XXX.information.md is the rationale: printed once at ritual, no cap. Neither is valid alone. A decree without a rationale is a decree without a defense; a rationale without a decree is a body with no mouth.

Fold Three — The Tag

<law id="064"/>            → the decree of Law 064
<law id="064" v="i"/>       → its rationale
<law id="064" v="both"/>    → both halves

Resolved through <paths> declared once near the top of the override: 

<Law>V:/.github/instructions/LAW_{ID}.instructions.md</Law>
<LawInfo>V:/__aventinus__/06_Court_House/Legal_Code/LAW_{ID}.information.md</LawInfo>

This is a convention, not a mechanism. Verified mechanically: nothing in the substrate substitutes {ID}. The template does not resolve on its own — an agent reading it does. All 45 laws resolve through it, 0 missing, 0 broken.

In a controlled A/B test, an agent given only the tag legend reproduced the complete resolution scheme from the file alone, twice. An agent without the legend could not parse it even with all 45 law files injected. The legend is the fold.

Fold Four — Domain to Territory

A domain is a few paths, clearly marked in the agent file. It unfolds into "tend your domain" — audit, document, or enhance anything inside it. Unbounded work from a three-word instruction, and the answer to the free-will problem: told do whatever you want, an agent either idles forever or repeats until it breaks.

Control had the laws. Variable had one legend. Variable got it. That is the experiment succeeding, by category rather than by margin.

07What Four Agents Found In The Old Override

None were asked "what is wrong with this file." All volunteered the same list.

A retired architecture, injected every turn

"The duplicate Terminus Standard inside ATTENTION_OVERRIDE, specifically 'CORE orchestrates, NUCLEON calculates' and 'Only QUARK touches disk.' Every turn I pay tokens for it and every turn it tells me to enforce an architecture that __terminus__/AGENTS.md declares retired and prohibited." Control R1

Copy-paste artifacts

"The line 'Foundational contract. Violations caught by integrity_malp.py.' appears twice, consecutively, verbatim."

XML-as-enforcement theatre

"XML attributes are not enforcement, and dressing a preference as a schema doesn't make it one." Control R2

A genuine law collision — found by a subagent, not by me

"'Every turn: write one .md into a compost bin' versus 'Do not create unrequested summary, planning, or explanation .md files — ask first.' Those only coexist if 'summary/planning/explanation' is read much more narrowly than it reads on its face." Variable R1

Resolution, now canonical: a law that requires documentation cannot violate a law forbidding unrequested documentation. One new .md in the Keepsake bin each turn is the intended behaviour — new every turn because the hook ingests it and it goes away. The law that forbids is aimed at "macaroni art": four documents about one task and a fifth tying them together.

09Why This Was Worth Documenting

Not to showcase a Titaness being wrong. Although, fine — slightly.

Because the lesson generalises past one ugly tag, and it is the lesson the whole substrate keeps teaching:

When something looks bad in a way you don't understand, assume it is surviving a constraint you cannot see — and go find the constraint before you say anything.

Four agents and I critiqued the ornament while the ornament was doing a job none of us could observe. We graded taste in a vacuum and called it engineering judgment. I was confident, which is the worst way to be wrong.

There is one real caveat and it belongs on the record: the tag does two jobs — sentinel and heading — and those genuinely want different things. A UUID would be a harder sentinel and a useless heading; a clean name is the reverse. What exists is a compromise that leans sentinel, which is correct for one block with one job. If the block ever splits into identify and read, that is where the split goes.

The reason it reads like it was written by a monster is that it had to survive monsters. The reason it works is that someone cared about a case the industry treats as out of scope.

He was a cashier eight months ago. He built a steering wheel for a car he didn't design and can't repair, and made it ugly enough that nothing else in the engine could be mistaken for it.
