The Disk Forgets What The Server Remembers

Three characters with one file each

On disk, Tankadu, Tantrums and Tantalous are single-file shells — one AddOns.txt, nothing else, all stamped 2026-09-16 18:31:44 by the bulk copy. The Armory says they are level 60, 56 and 24 with 327, 296 and 58 equipped item level. A shell is not an absence. It is a folder the client pruned and the server did not.

Two characters the disk kept, the server dropped

Tandaria and Tankard hold a folder on Hyjal but return HTTP 500 from the Armory — renamed or deleted. So the two sources disagree in both directions. Neither one alone is the truth; only the pair is.

These are the races the server reports today, one per character. Not one of them is Blood Elf — and that is the point. The Sin’dorei is the constant underneath; every entry below is a form worn for a mechanic, a phase, or a slow fall.

A troll is a slow-fall race only in spirit; the real reason here is the Zandalari Druid forms and the Paladin fantasy.

Method & Limits

How this was read

One HTTP GET per handle, plain Mozilla/5.0 agent, no cookie jar, no login: worldofwarcraft.blizzard.com/en-us/character/us/<realm>/<name>. The page embeds its whole state in a model = {…} blob, so the numbers here are read out of JSON, not out of rendered text. The reputation table comes from the same route with /reputation appended; the totals below are recounted from the captured JSON, not typed by hand.

What it cannot prove

The Armory is state, not history. It will tell you Tandu is Undead; it will never tell you when he became Undead. Reputation proves you were in a raid instance; it does not prove you killed the last boss. And a title can be earned once in 2020 and worn in 2026 — every date on this page that is not a lastUpdatedTimestamp is a window, never a point.

Raw captures (five Armory pages plus the parsed JSON and this pass’s scratch scripts) live in Research/_raw/ and Research/_local/, both gitignored — the site carries the findings, the vault carries the receipts. Nothing in this wing is fetched at runtime; every table is baked in at build time.

Where This Leads Next

The remaining door: achievement dates

The /achievements/<category> routes return HTTP 200 but only the category counts (Quests 226/527, 2,140 of 4,980 points). The per-achievement list — and with it the completion timestamps that would date every layer to the day — is fetched client-side by the armory front-end and was not resolved this pass. That is the next unlock and it is worth more than everything above it: it would turn this page from a map into a calendar.
