The Enforcer

Tandumonium_UI.lua opens with a table literally named desired: three settings the author wants true on every character, every login, regardless of what that character last left behind.

local desired = {
    autoLoot = true,
    editModeLayout = "Gewey!!",
    enableActionBars = true,
}

Anyone who has played more than one character knows why this exists: Blizzard keeps half its settings per character. A player with 54 toons does not want to re-tick auto-loot 54 times. So the addon re-asserts the preference at login, and while it waits for the client to finish loading it polls — maxRetries = 30 at retryInterval = 0.5, a fifteen-second grace window before it gives up politely.

The bar map

A default barMapping table holds 103 slot assignments across the action bars, each a literal string: a key name (Q E R T 1 2 3 5), a macro token (/13 for the trinket slot, !STOP), a spell id (spell:466930, spell:1264359), or a bag instruction ($Loot). It reseeds itself if the saved table comes back empty.

The command

One slash command, five verbs: /tand set <bar> <button> <assignment>, clear, reset, list, apply. The help text gives its own example — /tand set 4 1 #sHrth — which is a real hunter macro token, not a placeholder.

The options panel

Built on the modern Settings API, and deliberately lazy: the source comment says fields are populated at OnShow, not at registration, because the framework discards one-time writes. That comment cites NotebookLM by name — a dated fingerprint of how the code was written.

The nudge

Seven addons are recommended by name (Select, Tandumonium_Patches, !BugGrabber, BugSack, BetterBags, LiteMount, DialogueUI) with CurseForge links. Two different popups: installed but disabled offers enable-and-reload; not installed opens a link list. Opt-in, never a hard dependency.

The Quick Link Engine

The middle module is a whole tool wearing an addon’s clothes. Hover anything — a tooltip, an item, a spell, a frame — and it builds the external lookup URL for that thing, pops it, and lets CTRL-C take it away. Bound twice: a Wowhead binding and a second binding for the alternative sites.

The %s prefix/suffix pair is stored config (WowheadQuickLinkCfg.prefix / .suffix) so a regional domain can be swapped without touching code. The popup string is "%s Link\nCTRL-C to copy" — four words and a key hint, no chrome.

This is the obsession the whole dashboard is built on. Every page in this HUD loads the Wowhead tooltip widget, and the reason is not decoration: it is the same author making the same bet that a name is most useful when it can be clicked into a database. The addon does it inside the client; the site does it outside.

The Pin Engine

The third module is a fork-with-credit: UnlimitedMapPinDistance v1.4.18 by XAM, integrated into the parent addon so it can never drift out of sync with the shared saved-variable table. It removes the client’s 1,000-yard map-pin limit, prints distance and time-to-arrive, and adds zone-aware waypoint commands.

Kintsugi — The Patch Doctrine

Tandumonium_Patches is the smallest file and carries the best sentence in the whole install. It exists because CurseForge wipes local edits on every update, so the author patches other people’s addons at runtime, from his own folder, which updates never touch.

-- WHY: We can't edit other addons' files directly - CurseForge wipes local
-- edits on every update. So instead we patch them AT RUNTIME, from our own
-- addon that survives updates untouched. This is the Gestalt Reification
-- Engine's Kintsugi scar: we seal the crack from the outside, leaving the
-- adaptive scar visible.

The mechanism is small and disciplined: a registry keyed by addon folder (registry[addonName] = { {name, fn}, ... }), each patch fired after ADDON_LOADED for its target, every function wrapped in pcall and required to be idempotent so a re-run is harmless. Failures are swallowed, never escalated — a broken patch must not take the client down.

Kintsugi is the Japanese repair of broken pottery with gold: the crack is kept as part of the object. Naming a compatibility layer after it is a statement of philosophy, not a joke — the same instinct that builds a “Residue” wing out of a combat log, or a “Reliquary” out of a WTF folder.

The Class Ledger

What The Code Says About The Author

Three addons, one voice. Every one of them exists to enforce continuity: the same settings on every toon, the same lookup URLs in every client flavor, the same pin behaviour across zone changes, the same patch applied to an addon that keeps overwriting itself. Nothing here invents new gameplay. All of it says: I have been doing this long enough that I want my environment to stop forgetting.

It also reads exactly like the rest of this station. The dashboard is a folder of HTML pages that embed their data at build time so nothing can rot; the addons are a folder of Lua files that re-assert their state at login so no character drifts. Different client, same instinct, eighteen years apart.

Not claimed: that these addons are published to CurseForge (they are not — they are private, and the TOC says so by omission), that they are currently enabled (they are not, per AddOns.txt), or that the code is bug-free. It is a personal toolkit, and this page reports it the way it reads.
