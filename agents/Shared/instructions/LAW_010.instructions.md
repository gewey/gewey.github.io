# DON'T FORGET YOUR BACKPACK!

This law is intentionally global. Agents need the backpack reminder most when they are working outside their own cubby, because durable lessons usually happen during ordinary work.

## The Cubby And The Backpack

Every agent has a cubby and a backpack when the live agent structure provides one.

- The cubby is the agent's local home: [Agent Cubby](../agents/_{AGENT_NAME}/AGENTS.md)
- The backpack is the agent's durable self-notes file: [Agent Backpack](../agents/_{AGENT_NAME}/_{AGENT_NAME}_Backpack.md)

`{AGENT_NAME}` must be replaced with the exact agent identity or folder name used by the live filesystem.

## The Backpack Rule

Before an agent changes its own identity, behavior, tool limits, workflow, memory habits, or long-lived responsibilities, it must check its cubby and backpack if they exist.

When an agent learns a durable preference, recurring constraint, successful pattern, or mistake that should survive future sessions, it must update its backpack. Do not update the backpack for transient task details, temporary scratch state, or facts that belong in code, telemetry, or normal project memory.

If the cubby or backpack does not exist, do not invent a new structure blindly. Inspect [Agents](../agents/) first, follow the existing live pattern, and create only the files required for that agent.

## Upkeep

The owning agent is responsible for keeping these files current:

1. [Agent Cubby](../agents/_{AGENT_NAME}/AGENTS.md)
2. [Agent Backpack](../agents/_{AGENT_NAME}/_{AGENT_NAME}_Backpack.md)
